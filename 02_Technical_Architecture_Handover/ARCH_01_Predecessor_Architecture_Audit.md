# 🔍 ARCH-01: Predecessor Architecture Audit (ผ่าตัดสถาปัตยกรรมเดิมและหนี้ทางเทคนิค)

> **รายงานสำหรับ:** ทีมพัฒนาชุดใหม่ที่รับไม้ต่อ  
> **ระดับความเสี่ยงทางเทคนิค (Risk Level):** 🟡 ปานกลาง (ด้านโค้ดดิ้ง) | 🟢 ต่ำมาก (ด้าน Asset/Map เพราะทำไว้ดีมาก)  
> **หัวใจสำคัญ:** โค้ดเดิมทำงานได้ในระดับ Prototype คันเดียว/คนเดียว แต่ยังไม่พร้อมสำหรับเซิร์ฟเวอร์ Multiplayer สเกลจริง

## 1. จุดเสี่ยงและข้อผิดพลาดทางสถาปัตยกรรม (Architectural Pitfalls Found)

### 🔴 ข้อที่ 1: สคริปต์ฝังตัวใน Workspace (Workspace-Embedded Scripting Anti-Pattern)
- **ปัญหาที่พบ:** 
  - สคริปต์ควบคุมรถ `VehicleSystems` และหน้าปัด `CarStatusGui` ถูกยัดไว้ข้างในโมเดลรถแต่ละคันตรงๆ
  - สคริปต์ระเบิดถังน้ำมัน `BarrelExplosions` ฝังอยู่ในโฟลเดอร์ถัง
  - สคริปต์หมุนเสาฟาร์ม `TotemAnimation` มีก๊อปปี้ซ้ำกันถึง 3 ตัว ในแต่ละแท่นฟาร์ม
- **ผลเสียร้ายแรง:**
  - **Memory Leak & CPU Waste:** หากมีรถ 20 คันในเซิร์ฟเวอร์ จะมีลูป `Heartbeat` และ `while car.Parent do` รันซ้ำซ้อนกัน 20 ชุดพร้อมกัน
  - **ดูแลรักษาโค้ดยาก:** ถ้าต้องการแก้สูตรดาเมจรถ ต้องตามแก้ในโมเดลรถทุกคันในแมพ

### 🔴 ข้อที่ 2: วัตถุจำลองถูกวางทิ้งใน Workspace โดยไม่มีระบบ Spawner
- **ปัญหาที่พบ:** รถ Tesla Roadster ถูกวางแช่ไว้ในฉาก 2 คันตั้งแต่เริ่มเกม
- **ผลเสีย:** 
  - เมื่อรถชนพัง เลือดหมด หรือน้ำมันหมด รถจะกลายเป็นซากค้างอยู่ในเกม ไม่มีการทำลาย (Despawn) หรือรีเซ็ตสภาพ
  - ผู้เล่นคนอื่นไม่สามารถเบิกรถของตัวเองได้ เพราะไม่มีระบบ Instantiate จาก ServerStorage

### 🔴 ข้อที่ 3: สคริปต์แอนิเมชั่นภาพรันบน Server แทนที่จะเป็น Client
- **ปัญหาที่พบ:** สคริปต์ `TotemAnimation` ใช้ `RunService.Heartbeat` รันบนเซิร์ฟเวอร์ แล้วสั่งเปลี่ยน `CFrame` ของชิ้นส่วนหมุนตลอดเวลา
- **ผลเสีย:** 
  - การเปลี่ยน CFrame บน Server ทำให้เกิดการ Replicate ส่ง Network Packets ไปหาผู้เล่นทุกคนตลอดเวลา กินแบนด์วิธเครือข่ายและทำให้เซิร์ฟเวอร์กระตุก (TPS ดรอป)
  - **หลักการที่ถูกต้อง:** การเคลื่อนไหวของวัตถุฉากที่ไม่มีผลต่อฟิสิกส์การชน ควรส่งไปคำนวณบนไคลเอนต์ (`RenderStepped` บน LocalScript)

### 🔴 ข้อที่ 4: ขาดชั้นการสื่อสาร Client-Server Networking (0 RemoteEvents)
- **ปัญหาที่พบ:** ใน `ReplicatedStorage` ไม่มี `RemoteEvent` หรือ `RemoteFunction` แม้แต่อันเดียว
- **ผลเสีย:** ระบบทุกอย่างสื่อสารกันผ่านการเช็ค Attribute หรือ ObjectValue ซึ่งมีความล่าช้า ไม่เป็นทางการ และไม่สามารถทำ Rate Limiting ป้องกันโปรแกรมโกง (Exploit Defense) ได้

## 2. ตารางเปรียบเทียบ: โครงสร้างเดิม vs โครงสร้างใหม่ที่แนะนำ

| ประเด็น | โครงสร้างเดิม (Predecessor) | โครงสร้างใหม่ที่ต้องปรับ (Modern Target) |
| :--- | :--- | :--- |
| **ตำแหน่งสคริปต์เซิร์ฟเวอร์** | ฝังใน `Workspace.Model` | รวมศูนย์ใน `ServerScriptService` |
| **ตำแหน่งตัวรถยนต์** | วางค้าง 2 คันใน `Workspace` | เก็บ Template ใน `ServerStorage.Vehicles` แล้ว Spawn ตามคำสั่ง |
| **การคำนวณแอนิเมชั่นฉาก** | `Heartbeat` ฝั่งเซิร์ฟเวอร์ | `LocalScript` ฝั่งผู้เล่น (Client-side Visuals) |
| **การส่งข้อมูล UI รถ** | โคลน ScreenGui เข้า `PlayerGui` สดๆ | จัดเก็บใน `StarterGui` แล้วซิงค์ข้อมูลผ่าน Attributes/Remotes |
| **จุดเกิดผู้เล่น** | ไม่มี (เกิดสุ่มที่ 0, 100, 0) | สร้าง `SpawnLocation` ที่จุดปลอดภัยหน้าโชว์รูม |

## 3. สรุปความคุ้มค่าของการรับไม้ต่อ (Handover Value Assessment)
แม้โครงสร้างโค้ดเดิมจะต้องได้รับการจัดระเบียบใหม่ (Refactoring) แต่สิ่งที่มีมูลค่ามหาศาลที่ได้รับมาคือ:
1. **Asset แผนที่และเลเอาต์เมืองระดับมืออาชีพ** (ประหยัดเวลาทำแมพไปกว่า 100+ ชั่วโมง)
2. **ระบบฟิสิกส์การขับรถและคำนวณดาเมจที่ผ่านการทดสอบมาแล้ว** (มีสูตรตัวเลขการชนและลดน้ำมันที่สมดุล พร้อมหยิบไปใส่ Service กลางได้ทันที)
